# 第一部分　一页速记（上台前扫一眼）

## 每题一句话

### 架构类

- 1　框架：分四层——服务层 Python + FastAPI，WebSocket 一条长连接；Agent 层自研轻量框架（BaseAgent + 协作协议）；模型层统一 OpenAI 兼容协议（无密钥自动降级 Mock）；编排层自研 TaskGraph，兼容 LangGraph；对外 MCP + A2A。
- 2　LangGraph：双轨，默认自研保底、LangGraph 可选；共用同一批节点方法，专项测试钉住行为一致。
- 3　通用性：四件事——模型可插拔、编排可切换、角色可扩展、协议标准化；技能是 Markdown 不是代码；局限 = 会话在内存，多机要换 Redis。
- 4　RAG：检索三层（字符 bigram 余弦 → 有向量服务自动切）；离线六阶段流水线；只两个时机用（讲知识点注入、ReAct 自查证）；出题不用 RAG，直查真题库；检索失败静默降级，绝不阻断上课。
- 5　Skill / MCP：教师技能 11 份 Markdown、Agent 技能 4 个 Python；MCP 6 工具双接入（stdio / HTTP）；A2A Agent Card + 6 态状态机。
- 6　技能更新：人改 md 即时生效、后台校验 + 备份；机器每回合复盘、只追加、0.85 去重、Thompson 采样按战绩决定注入。
- 7　评估：四层——53 文件 600 用例 / 12 题 9 学科各半打分、跌 3 分判回归、TSV 可 diff / RAGAS 四维 + 多轮 / L0 裁决 + L1 健康 + L3 聚类；延迟目标 1.2s、300ms、120ms。

### 产品与设计类

- 1　对标：1 对 1 + 数字人直播 + 技能管理后台；优势四条——无人值守 / 实时链路工程化 / 质量靠机制 / 换老师不改码；合规内建。
- 2　Skill 设计：Markdown 是事实源，Python 只解析注入；配置头 + 九项行为固定标题 = 契约，单测钉住。
- 3　多用户：会话级并发、按学生分文件隔离可物理删除、PBKDF2 + JWT、学生 ID 以服务端为准、签名 + 限流；局限 = 会话内存要 Redis。
- 4　md + python：md 管内容，python 管机制；执行型技能必须代码；程序永不改写技能本体，经验只能追加。
- 5　专家调用：按职责切不按学科切；规则直判优先、小模型复核兜底；总控走固定决策树；学科差异靠技能文件；技能调用由 ReAct 自主决定。

### 调度与机制类

- 1　Manager：独占状态不产内容；白名单分发；入队瞬间抢占作废旧播报；四级降级不哑巴。
- 2　几个 Agent：总控 / 答疑 / 讲课 / 学生代理 + 意图决策层；零直接调用，靠共享状态 + 消息总线 + 事件扇出；状态 = 内存主存 + 断线检查点 + append-only JSONL。
- 3　State：内存主存、总控独占；落盘时白板 500、历史 200；追加式更新；写库后台线程，失败不阻断。
- 4　亮点：无人值守闭环 / 实时链路工程化 / 自主性四层可关 / 质量可度量闭环。
- 5　回测：不做投资回测；三套等价 = 质量回归门禁 + 过程回放 + 收益后验。

### 工程实现类

- 1　队列：asyncio.Queue 每连接一条；生产者 = WS 接收协程，消费者 = 会话主循环，0.5s 超时帧；解决串行化、不丢、入队即打断；配速信号就地处理不入队。
- 2　实时互动：全链路流水线；四样互动 = 麦控 / 打断 120ms / 追问 1+2 / 空闲 30s 最多 3 次；四段编排 75/25 = 讲解 30 + 出题 10 分钟；前端计时驱动后端映射；30 分钟自动出题；服务端计费。
- 3　微调：不做微调，走推理侧；在线可切 OpenAI / DeepSeek / 私有化 Qwen3，离线保底 Qwen2.5-7B-Instruct-AWQ；4090 24G 常驻 17.2G，双驻留建议 48G；数据在六阶段教研流水线。

## 危险题口径

- 回测：不做投资回测；等价的是质量回归门禁 + 过程回放 + 收益后验回写。
- 微调：不做微调，走推理侧；数据集中在流水线清洗、脱敏、门禁。
- LangGraph：双轨，默认自研、LangGraph 可选，两份实现一份契约，测试钉住。
- 核心竞争力：不让 AI 老师靠运气讲课——每个环节都有机制保证质量稳定，而且质量是可以度量的。

# 第二部分　七处必改（答辩前逐个背改口）

### 1　别说「从结构上不可能分叉」

- 改口：「两份实现、一份行为契约，专项测试钉住」。
- 原因：两条编排轨各写各的调度，但共用同一批节点方法；一致性测试用同一组输入跑两条链路、断言副作用一致。

### 2　别说「白板最多 500 条、历史 200 条」

- 改口：「断线检查点落盘时，白板留最近 500 条、历史 200 条」。
- 原因：500 / 200 是落盘截断口径，运行期内存不设硬上限。

### 3　别说「每节课后复盘」

- 改口：「每个答疑回合结束后异步复盘，有最小间隔节流」。

### 4　别说「CI 直接拦」

- 改口：「门禁脚本返回非零码，可挂到 CI 或上线前拦截」。

### 5　别说「大脑是 Qwen3、本地 AWQ 7B」混成一句

- 改口：「在线可切 OpenAI / DeepSeek / 私有化 Qwen3；离线保底是 Qwen2.5-7B-Instruct-AWQ」。

### 6　别说「三者对齐有单测钉住」

- 改口：「技能目录与学科配置有单测钉住；教师素材缺失时回退 persona，不崩」。

### 7　别说「安全审计按主体分文件」

- 改口：「记忆按学生、经验按老师、战绩按技能、裁决按天；安全审计是独立单文件审计流」。

### 另外两条别硬说

- BaseAgent 里没有抽象方法，只有 role 标识 + 会话开始 / 结束两个生命周期钩子。
- 1 对 1 页面的课程阶段条已停用，别说「页面上有进度条」。

# 第三部分　完整答题稿

## 第一批　架构类

### 1. Agent 用了什么技术框架？

- 定调：分四层说，报框架名等于没答。
- ① 服务层：Python + FastAPI，实时通信一条 WebSocket 长连接，入站出站各一条异步队列。
- ② Agent 层：自研轻量框架，不是 LangChain 套壳。全部家当三样：一个 BaseAgent 基类（role 标识 + 会话开始 / 结束两个钩子 + 会话实例按参数传递）、一套协作协议（共享状态、消息总线、事件扇出）。
- ③ 模型接入层：统一 OpenAI 兼容协议，ChatGPT / DeepSeek / 私有化 Qwen3 改环境变量就切；没配密钥自动降级 Mock，零密钥也能跑通全流程。
- ④ 编排层：自研 TaskGraph——拓扑序执行、编译期环检测、skip / stop 控制键，同时提供 LangGraph 轨。
- 对外：工具走 MCP，被外部 Agent 调用走 A2A。
- 追问「框架薄在哪」：薄到两条编排轨能共用同一批节点方法，能用一个测试文件钉住两条链路的等价性。

### 2. 为什么用 LangGraph？

- 定调：双轨，不是非它不可——这题答「取舍」。
- ① 默认轨：自研图引擎，零额外依赖，缺库照跑，保底。
- ② 可选轨：LangGraph，提供标准 StateGraph 语义，方便对接企业生态；依赖缺失会自动回退并告警。
- ③ 一致性：两轨共用同一批节点方法和同一份共享状态，行为一致性有专项测试：同一组输入跑两条链路，断言副作用一致。
- 追问「两份实现怎么保证不分叉」：不自欺说只有一份实现，是「允许两份实现、不允许行为分叉」，用测试钉死行为契约，差异在测试阶段暴露。

### 3. 通用性 Agent 是什么样子的？

- 定调：通用性 = 四件事可替换，加两条局限如实说。
- ① 模型可插拔：四类能力统一接口，换供应商只改环境变量。
- ② 编排可切换：自研轨 + LangGraph 轨双轨。
- ③ 角色可扩展：新增 Agent 只需继承基类。
- ④ 协议标准化：MCP 出、A2A 进。
- 技能不是写死的代码，是 11 份 Markdown，改文件就改行为。
- 局限：会话状态在进程内存，多实例要换 Redis；A2A 卡片里 streaming、pushNotifications 明确声明为 false，不夸大能力。都在规划里，没藏。

### 4. 主要优化？什么时候用 RAG？

- 定调：检索三层 + 流水线一条 + 时机两处 + 出题不用。
- ① 主链路：轻量字符 bigram 余弦相似度，零依赖。
- ② 有向量服务时自动切成语义向量检索。
- ③ 离线：直播录像 + 课件 + 答疑记录，加工成教研数据，六阶段流水线：解析 → 清洗脱敏 → 教学语义切分 → 机器预标注 → 问答挖掘 → 门禁导出。
- ④ 在线问答是独立重依赖链路，缺依赖就不启用，不拖主链路。
- 用 RAG 只有两个时机：讲知识点时检索题库、注入提示词；模型在 ReAct 闭环里自己决定查证。
- 出题不用 RAG：直接查结构化真题库，答案链是「真题库 → LLM → 规则」三级降级。结构化数据不需要向量检索，这是判断不是偷懒。
- 检索失败静默降级纯大模型，绝不阻断上课。

### 5. Skill、MCP 涉及哪些？

- 定调：技能两类共 15 份，MCP 6 工具双接入，A2A 完整进。
- ① 教师技能：11 个学科各一份 Markdown，路径 .agents/skills/学科key/SKILL.md，管人格 + 九项教学行为。
- ② Agent 技能 4 个，Python 实现：答对表扬、翻学生历史错题、查教学经验、取学科讲法（参考型无执行体，运行时现读该学科 SKILL 的讲课方式）。
- ③ MCP 6 个标准工具：题目识别、知识检索、白板写入、白板清空、解方程、答案验算。支持 stdio 本地进程和 Streamable HTTP 两种接入，任何 MCP 客户端可直接调。
- ④ A2A：Agent Card 两个发现端点（兼容 0.2 / 0.3）加 JSON-RPC 入口；任务状态机 6 态：submitted / working / input-required / completed / canceled / failed。

### 6. Skill 怎么更新？

- 定调：两条通道，人管本体，机器长经验，边界不越。
- ① 通道一（人）：改 Markdown 即时生效，不重启不发版；解析缓存按文件修改时间自动失效；管理后台只有 admin 能进，保存前结构校验（不通过直接拒收）、自动 .bak 备份、有路径穿越防护。
- ② 通道二（机器）：每个答疑回合结束后异步复盘，有最小间隔节流；只追加，绝不改写人格本体；相似度 0.85 去重、限量；注入哪几条由 Thompson 采样按实战收益决定——裁决通过记 1、降级或失败记 0，是带反馈的，不是拍脑袋；表现差的进人工抽检台。
- 追问「机器学的经验会污染人格吗」：物理上不可能。经验存独立 JSONL，注入是「追加在技能之上」，程序里没有任何改写本体的代码路径。

### 7. 有哪些评估？

- 定调：四层，每层都能落到文件。
- ① 单元测试：53 个测试文件、约 600 个用例（参数化收集后 700+），全 Mock 可跑。
- ② 质量评测：走真实生产链路，12 道题覆盖 9 个学科；规则分判结构完整性，裁判分由大模型按要点覆盖、正确性、好懂度打分，各占一半；可设基线，改动后重跑，跌超 3 分判回归；门禁脚本返回非零码，可挂 CI；每轮结果追加一行 TSV，能进 git 用 diff 看质量趋势。
- ③ RAG 专项：RAGAS 四维（faithfulness、context_precision、context_recall + 自实现 answer_relevancy，不可用自动降级）；另有多轮对话评测 12 组 26 轮。
- ④ 运行时观测：L0 回合裁决落盘、L1 健康诊断（四维健康画像 + 先行退化信号）、L3 失败聚类（失败签名聚类 + 根因分析）。
- 延迟目标量化：语音响应 1.2 秒、音画同步 300 毫秒、白板同步 120 毫秒，写在常量里。

## 第二批　产品与设计类

### 1. 工作台对标什么？优势是什么？

- 定调：产品形态三段，优势四条，合规内建。
- ① 形态：学科选择页 → 1 对 1 辅导主页 → 教师监控台 + 技能管理后台。
- 对标市面：前两块约等于在线 1 对 1 + 数字人直播，后台约等于技能管理平台。
- ② 优势一：全流程无人值守，讲题、板书、追问、出题、判题、表扬一条龙。
- ③ 优势二：实时链路工程化，延迟目标量化，支持插话打断和智能麦控。
- ④ 优势三：质量靠机制不靠人，同一位老师每节课标准稳定。优势四：换老师只换素材，不改代码。
- ⑤ 合规内建：安全过滤是每次输出的必经环节，有独立安全审计落盘，不是事后抽检。

### 2. Skills 怎么设计，什么规则？

- 定调：Markdown 是事实源，Python 只做解析和注入。
- ① 一份 Markdown 承载两层：frontmatter 配置头（语速、深度、风格等），正文是固定标题小结。
- ② 九项教学行为：开场方式、追问方式、鼓励方式、表扬方式、纠错方式、学生说「我不会」时、学生连续答错时、白板组织、语气与节奏。
- ③ 标题是契约，逐字匹配，改了标题就解析不到；九项有单测钉死「必须逐字齐全」，管理后台保存走同一张校验表。
- ④ 纪律：技能目录与学科配置有单测保证一致；教师素材缺失或缺 Markdown 时自动回退档案里的 persona，绝不崩。
- ⑤ 运行时现读现改现生效，调话术不用发版。

### 3. 多人调用 Agent，怎么管多用户？

- 定调：四个维度：并发、隔离、身份、安全。
- ① 并发：一条连接一个会话、一个会话一条队列，会话表加锁。
- ② 隔离：学情记忆按学生物理分文件，同名也隔离，支持整份物理删除，满足未成年人合规。
- ③ 身份：落 MySQL，PBKDF2-SHA256（20 万次迭代）+ JWT；REST 走请求头，WebSocket 走 token 参数；认证通过后学生 ID 一律以服务端用户表为准，忽略前端自报值。
- ④ 安全：接口签名校验 + 滑窗限流防逆向；外部 Agent 调进来走独立会话前缀，不打断课堂。
- 局限：会话表在内存，多实例要换 Redis，规划里写明了。

### 4. Skills 应该是 md 文档 + python？

- 定调：对，分工是硬的：md 管内容，python 管机制。
- ① 为什么不全用 md：执行型技能必须带判断逻辑和入参约束，那是代码的活。
- ② 人格类技能全部放 md。
- ③ 4 个带执行体的 Agent 技能是 python 实现，但执行纪律是声明式的。
- ④ 程序永不改写技能本体，经验只能追加在它之上。

### 5. 专家如何调用，规则是什么？

- 定调：按职责切，不按学科切。
- ① 角色：答疑 TeacherAgent、讲课 LecturerAgent，总控分发。
- ② 入口先过意图决策层：高频输入规则直判，不花模型额度；拿不准或多意图才调小模型复核，超时失败一律回退规则结果。
- ③ 总控走固定决策树：待答的追问优先判题、不重新路由；多意图逐条独立作答；控制指令当场执行。
- ④ 学科差异不靠新 Agent，靠技能文件；技能是否调用由模型在 ReAct 闭环里自主决定，不是硬编码。

## 第三批　调度与机制类

### 1. Manager Agent 怎么调度？

- 定调：独占状态、只管顺序，核心机制是「入队即抢占」。
- ① 总控一次会话一个实例、独占会话状态，自己不生成任何教学内容。
- ② 上行事件白名单分发，未知事件静默忽略。
- ③ 抢占：学生发新消息的入队瞬间就作废旧播报（世代号自增 + 推打断信号 + 中止自动播报），不等旧回合跑完。否则旧回合几十秒，新问题只能排队尾，体验就是「老师还在讲上一题」。
- ④ 退路四级：讲课失败降级念本页要点 → 再失败走等价实现 → 再失败给兜底话术 → 播报层还有「数字人 → 纯语音 → 前端朗读」降级，绝不哑巴翻页。

### 2. 项目有几个 Agent？怎么交互？状态怎么保存？

- 定调：四角色一决策层，零直接调用。
- ① 角色：总控、答疑、讲课、学生端代理；意图决策层是决策层不是 Agent，不参与消息总线。
- ② 交互靠三件事，没有互相直接调用：共享状态（唯一黑板，总控独占，其他人只拿引用不改）、消息总线（只记转交和异常，环形缓冲 80 条）、事件扇出（推前端可回放）。
- ③ 状态：内存主存 + 断线检查点落盘；记忆按学生、经验按老师、战绩按技能、裁决按天，各存 append-only JSONL；安全审计单独一条审计流。

### 3. State 存在什么地方？怎么更新？

- 定调：内存主存、追加式更新、写库不阻断课堂。
- ① 主存内存，总控独占，其他人只读引用。
- ② 持久化：断线检查点存白板和对话历史——落盘时白板留最近 500 条、历史 200 条；其余按主体、按天分文件追加。
- ③ 更新全是追加式：白板指令追加、插话计数器自增作废旧播报、追问状态写和清。
- ④ 写库走后台线程，失败只告警不阻断——观测和记账绝不能把课堂搞挂。

### 4. 项目的亮点是什么？

- 定调：四条，讲价值不讲功能。
- ① 全流程无人值守：多模态进、数字人出，一条闭环。
- ② 实时链路工程化：延迟目标量化，插话打断 + 智能麦控，学生一开口 AI 就闭嘴。
- ③ 自主性四层全是「可关的增强」：工具、ReAct、规划、记忆，各有独立开关，全关回到最小系统，新能力永不是新故障点。
- ④ 质量可度量：运行时裁决 → 健康诊断 → 失败聚类 → 真实链路回归门禁 → 经验自我更新，一条完整闭环，不靠人盯。

### 5. 回测的实现逻辑是什么？（危险题）

- 定调：先纠正概念，再给三套等价机制。
- ① 说清楚：我们没有交易策略那种回测，系统不做投资决策。
- ② 机制一，质量回归门禁：先跑评测定基线，改动后重跑，跌超 3 分判回归、门禁脚本拦在上线前；每轮追加一行记录可进 git，diff 一眼看出这次改动让质量动了多少。
- ③ 机制二，生产过程回放：节点级执行轨迹落盘，能回看某次答疑卡在哪一步。
- ④ 机制三，收益后验回写：经验和技能按实战战绩记账，注入策略用 Thompson 采样、收益由裁决结果回写，本质就是用历史数据优化下一步决策。

## 第四批　工程实现类

### 1. 消息队列怎么实现？生产者消费者是谁？解决什么问题？

- 定调：Python 原生异步队列，每连接一条，不引入中间件。
- ① 生产者：WebSocket 接收协程。
- ② 消费者：该连接的会话主循环，取事件分发总控，带 0.5 秒超时帧——不是干等，超时就去跑定时出题巡检，防饿死。
- ③ 解决三件事：回合串行化（共享状态不能被并发写乱）、事件不丢、「入队即打断」。
- ④ 例外：连讲的配速信号就地处理不入队——入队它会一直排不到，导致每页都卡一个超时。这个例外说明我们真跑过。

### 2. AI 讲课能否实时互动？40 分钟课程怎么编排？

- 定调：能，靠四样互动 + 四段编排。
- ① 链路：输入 → 识别 → 流式生成 → 逐句合成（首包 200 到 300 毫秒）→ 逐句渲染口型 → 播放，全程流水线。
- ② 互动四样：智能麦控（学生开口 AI 静默）、插话打断（120 毫秒宽限）、追问闭环（上限 1 次追问 2 次重试，防死循环）、空闲问候（静默 30 秒主动搭话，最多 3 次）。
- ③ 编排四段：热身、讲解、出题、总结；时间映射 75% / 25% = 讲解 30 分钟 + 出题 10 分钟；阶段由前端计时驱动、后端只做映射，不引入后端长驻定时器。
- ④ 讲满 30 分钟自动出模拟题，优先真题库，答对表扬、答错讲解；计费在服务端做，退出页面不停表，到点自动结算。

### 3. 有微调吗？（危险题）

- 定调：不做微调，走推理侧，成本花在推理和数据治理。
- ① 模型：在线统一 OpenAI 兼容协议，可切 OpenAI / DeepSeek / 私有化 Qwen3；离线保底是本地 Qwen2.5-7B-Instruct-AWQ，AWQ 量化直跑。
- ② 语音：零样本音色克隆，本身不需要训练；数字人是底片驱动渲染，也不需要训练。
- ③ 算力：AutoDL 云实例、RTX 4090 24G，全栈常驻约 17.2G / 24G；本地大脑和数字人同时驻留建议上 48G 卡，24G 上再启 AWQ 会 OOM。
- ④ 数据重头戏是六阶段教研流水线：解析 → 清洗脱敏 → 教学语义切分 → 机器预标注 → 问答挖掘 → 门禁导出；原则「机器做覆盖、人做判断」，机器产出必带人工审校标记，绝不直接入库。所以没有训练周期。

# 第四部分　危险题深挖：为什么不做 + 真做了会怎样

## 一、微调：为什么不做 + 真做了会有什么不一样

- 结论：不做微调，走推理侧。微调改的是「说话像不像」，改不了「讲课稳不稳」；我们的痛点在后者。

### 为什么不做（五条，按分量排）

- ① 架构上：我们已经把「可学习部分」外置了。微调是把学习写进权重——不可解释、难回滚、要重训；我们是把学习放在体外——经验存追加式 JSONL，注入用 Thompson 采样按实战战绩选，人格和话术在 Markdown 技能文件里。结果：可回滚、可审计、可热更新，粒度细到单个老师。
- ② 业务上：11 个学科 × 多位老师，一人一套人格。微调一个底座只能有一份「性格」，合训互相污染；分训要 N 份权重，24G 显存装不下。技能文件天然一人一份，改谁只动谁。
- ③ 数据上：教研数据的门禁原则是「机器做覆盖、人做判断」，机器产出必带人工审校标记、绝不直接入库。也就是说，能喂进模型的高质量数据还没到可训练量级，硬训就是过拟合加幻觉，风险大于收益。
- ④ 算力上：训练是另一个量级的投入，多卡长时间；我们现在 4090 24G 全栈常驻就 17.2G。同样预算投在推理稳定性和数据治理上，回报更高。
- ⑤ 迭代上：教学内容变化快——教材、话术、老师风格随时改。改 Markdown 即时生效、不发版；微调要重训、重跑评测、重新定基线，迭代周期从分钟级变天级。

### 如果真做了微调（两面都说）

- 好处（诚实承认）：语气更自然、更像真人老师；输出格式更稳定，JSON 解析失败率降低（我们现在有降级链兜着，微调能少触发几次）；提示词可以更短，省 token、省显存。
- 代价：换底座就白干（Qwen2.5 升 Qwen3 要重训，我们现在只改一个环境变量）；人格更新要重训（改一位老师的话术，从改文件变重训）；回滚困难（经验进权重后出问题只能换旧权重，我们的 JSONL 能 diff、能抽检、能逐条下线）；安全对齐要重新验证（安全过滤是链路必经环节，微调后照样得保留，收益重叠）；门禁负担翻倍（每训一次都要重跑 12 题评测和基线比对）。
- 收尾：微调能优化「像不像」，我们要保证的是「稳不稳」。稳不稳靠机制：技能契约 + 单测、评测门禁、运行时降级——这些是微调替不了的。

## 二、LangGraph：为什么双轨 + 只留一条会怎样

- 结论：双轨，默认自研保底，LangGraph 可选。

### 为什么自研当默认

- ① 零额外依赖：演示环境、云端缺库也能跑通全流程（云端真缺过依赖，主链路不受影响就是证据）。
- ② 行为可控：自研引擎能直接写单测钉住每一步，不存在大版本升级导致行为漂移。
- ③ 够用：拓扑序、环检测、skip / stop 控制键，教学编排不需要更复杂的图语义。

### 为什么还留 LangGraph 轨

- ① 提供标准 StateGraph 语义，企业生态对接方便。
- ② 外部团队接手时认知成本低。

### 只留一条会怎样

- 只有 LangGraph：依赖重、升级不可控、缺库就瘫。
- 只有自研：外部不好审、集成要额外解释。
- 两条都有：代价是维护两份实现——用一致性测试抵消：同一组输入跑两条链路，断言副作用一致。
- 一句话：把「标准」当可选项，把「能跑」当默认项。

## 三、回测：为什么没有 + 等价物为什么成立

- 结论：不做投资回测；等价的是质量回归门禁 + 过程回放 + 收益后验回写。
- 为什么没有：系统不做投资决策，没有「策略—收益」的确定性闭环。教学质量的收益是规则分 + 大模型裁判分，是主观评分不是盈亏。没有 ground truth 的回测，等于给自己发一张假成绩单。

### 为什么这三套算等价物

- 回测的本质是：上线前用历史数据验证策略、上线后优化策略。三套机制一一对应：
- ① 质量回归门禁 = 上线前验证：定基线、容差 3 分，跌了非零退出，拦在上线前。
- ② 过程回放 = 出问题定位：节点级执行轨迹落盘，能回看某次答疑卡在哪一步。
- ③ 收益后验 = 上线后优化：裁决收益回写 + Thompson 采样，等价于在线 A/B，用历史效果决定下一步策略。
- 如果硬做交易式回测：会得到一个看起来专业、但不可验证的指标，反而误导决策。诚实比包装值钱。

## 四、其它高频「为什么不」

- 为什么不用 LangChain：我们是薄壳，要的是能被测试钉住的行为；全家桶带来依赖和行为不确定性，它的收益在低代码编排，我们不需要。
- 为什么不引 Kafka / RabbitMQ：单机部署，消息只在一条连接内流转，不需要跨进程持久化；引入只增运维面和延迟。真要横向扩展，第一个动的是会话存储，不是消息队列。
- 为什么不一开始就上 Redis：单实例内存状态零依赖、够用；多实例是规划里的事，接口已按可替换设计，局限也如实讲，不藏。
- 为什么不全链路 RAG、出题不用 RAG：结构化数据不需要向量检索；向量链路有运维成本，只在语义模糊的开放问答里用。什么时候不用，比什么时候用更能体现判断。

# 第五部分　应答心法

### 万能句式（被问「为什么不做 X」就套）

- ① 先讲 X 解决什么问题。
- ② 再讲我们的等价方案，要可验证、带数字。
- ③ 最后讲真做了的代价和收益，包括「做了确实会好一点」的部分，不回避。顺序不能反：先认账，再讲取舍，最后给边界。

### 三条通用心法

- 1　每题先给一句话结论再展开，结尾补一句边界。
- 2　只报能落到文件名、常量、数字的事实，报出的数字要经得起追问两层。
- 3　不会的就答「当前的取舍 + 规划里的下一步」，这是加分不是减分。
